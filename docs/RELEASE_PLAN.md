## 2. Доступ: временный Cloudflare Quick Tunnel (план)

Схема: Quick Tunnel к одному loopback-сервису `http://127.0.0.1:8000`. UI: `https://<выданный-host>/`, API base: `https://<выданный-host>/api/v1`. Инференс остаётся на Mac. Cloudflare видит трафик как HTTP-посредник, включая загружаемые видео и ответы.

Свойства (по документации Cloudflare Quick Tunnels, ещё раз проверить перед запуском):
- аккаунт и домен не нужны; URL случайный, меняется при каждом запуске, исчезает при остановке процесса;
- uptime не гарантирован, Mac должен быть включён и не засыпать (смена настроек сна требует отдельного согласия);
- около 200 одновременных запросов, дальше 429;
- SSE не поддерживается; UI использует polling, поэтому это не мешает;
- Cloudflare Access с email-аутентификацией **несовместим** с API-вызовами жюри по ключу (нужен интерактивный вход), поэтому доступ защищает только `X-API-Key`.

Запуск сервера (на машине пользователя, не запускалось):
- `API_KEY` задаётся пользователем переменной окружения в момент запуска, в репозиторий и логи не пишется; ключ жюри передаёт пользователь сам, после мероприятия ключ меняется;
- `uvicorn app.asgi:app --host 127.0.0.1 --port 8000 --workers 1 --no-proxy-headers` (`TRUST_PROXY` не задавать): привязка только к loopback, туннель сам подключается к loopback; `0.0.0.0` не нужен (он нужен только при хостинге в сети без туннеля);
- `WORKERS=1` (не мешать stage 5 и не перегружать CPU); `UPLOAD_TIMEOUT_SEC=60` + `JOB_BUDGET_SEC=230` = 290 с < 300 с (проверяется `app/config.py`);
- веса `weights/yolox_s.onnx` уже на этой машине (`tools/fetch_weights.py` или копия); проверка `shasum -a 256`;
- проверка живости: `GET /healthz`; `GET /api/v1/model` с ключом: `allow_unvalidated_rules` должно быть `false`;
- в UI и README явно указано: production работает в режиме fail-closed, корректный клип в пределах лимитов завершается `failed/no_validated_rule`; иначе другой статический отказ (список в разделе минимального варианта).

Что не делать: не устанавливать туннель как постоянный сервис, не создавать токены и учётные записи, не пускать через туннель сервер разметки (порт 8790) и корень проекта.

### Открытый юридический вопрос (решает пользователь)

Применимость этой лицензии к транзитным видео через Quick Tunnel **не установлена**. Поэтому нельзя обещать, что провайдер не использует данные. ## 7. Риски (решения пользователя)

1. **Fail-closed может выглядеть как «нет детекции».** Жюри увидит `failed/no_validated_rule` для корректного клипа в пределах лимитов; иначе другой статический отказ (см. список в разделе минимального варианта). Это честно. Включение демонстрационного `ALLOW_UNVALIDATED_RULES=1` **не рекомендуется**; допустимо только локально в демо-видео или с видимым маркером «не валидировано».
2. **Кадры-доказательства (JPEG) уходят с машины** в браузер жюри и проходят через Cloudflare. Решение пользователя: оставлять ли их при публичном доступе или отключить для публичного режима (изменение кода, не выполнено).
3. **Условия Cloudflare** (раздел 2): не обещать, что данные не используются; настоящие видео через туннель не отправлять без отдельного решения.
4. **Нестабильность**: URL меняется, доступность зависит от Mac и сети; указать это в форме.
5. **Общий ключ**: утечка ключа даёт доступ к заданиям; после мероприятия сменить.

## Состояние защиты API (было «предложения», теперь реализовано api-dev; проверено по `app/main.py`)
1. `Cache-Control: no-store`, `Pragma: no-cache`, `X-Content-Type-Options: nosniff` на всех ответах `/api/*`, включая ранние 401/408/413/429.
2. `/docs`, `/redoc`, `/openapi.json` отключены (`docs_url=redoc_url=openapi_url=None`), ответ 404.
3. `.gitignore`: `*.onnx`, `*.safetensors`, `*.jsonl`, `.env`, `.env.*` (только правила игнорирования).
4. `REQUIRE_EMPTY_DATA_DIR=1` (opt-in): сервер отказывается стартовать при непустом `DATA_DIR`, ничего не удаляет. Использовать свежий пустой каталог при каждом запуске.
5. Лимиты: `MAX_INFLIGHT_UPLOADS` (по умолчанию 4), `RATE_LIMIT_PER_MIN` (30, POST), `POLL_LIMIT_PER_MIN` (600, опрос); корзины по IP socket peer (`scope["client"]`). Остаточное ограничение: проверка ключа выполняется ДО корзины POST, поэтому неверные попытки с ключом приложением не ограничиваются; защита от подбора ключа не заявляется (только длинный случайный ключ).
6. `BIND_JOBS_TO_KEY` (по умолчанию включено, `0` отключает): задание привязано к хешу ключа, чужой ключ получает 404. Привязка хранится только в памяти и пропадает при перезапуске.
7. Запуск: `--workers 1` (иначе лимиты и привязка не общие), `WORKERS=1` для минимального варианта (допустимо 1–2 вне него).

**Что увидит жюри.** Корректный клип в пределах лимитов завершится `failed/no_validated_rule` (fail-closed; детектора нарушений нет). Некорректный ввод и превышение лимитов дают другие статические отказы: HTTP 400 (плохой запрос), 401 (ключ), 404 (чужое/неизвестное задание), 408 (таймаут загрузки), 413 (файл слишком большой), 415 (тип не поддерживается), 422 (неверные поля), 429 (лимит частоты или число одновременных загрузок); коды ошибок задания `corrupt_video`, `too_long`, `too_few_frames`, `decode_error`, `time_budget_exceeded`, `worker_crashed`, `internal_error` и др. из закрытого списка. Утверждать «каждый клип -> no_validated_rule» нельзя. Демо-флаг `ALLOW_UNVALIDATED_RULES=1` **не рекомендуется** (выдал бы невалидированный результат за детекцию); допустим только локально в видео с маркером. Демо-MP4 прикладывается отдельно.

**Прокси-заголовки и общий лимит.** Туннель добавляет `X-Forwarded-For`, а uvicorn по умолчанию доверяет им от loopback. Поэтому запуск строго с `--no-proxy-headers`, `TRUST_PROXY` не задавать. Следствие (компромисс): весь трафик через туннель выглядит как один loopback-клиент и делит ОДИН общий лимит частоты и пул загрузок. Это честно и не обходится подменой заголовка, но означает, что один активный посетитель может исчерпать лимит для остальных жюри.

**Действия пользователя.** (1) сгенерировать ключ жюри в момент запуска; (2) запустить uvicorn с переменными окружения; (3) запустить туннель; (4) вставить URL и ключ в форму; (5) не давать Mac засыпать; (6) после окончания остановить туннель и сервер, сменить ключ; (7) приложить демо-MP4 отдельно.
